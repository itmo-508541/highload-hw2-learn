### Ответы на вопросы для самопроверки

1. консьюмер прочитает строго в том же порядке, в котором было положено в партицию с ключём.
        но без ключа порядок не гарантирован, потому что один консьюмер может обработать данные раньше другого
        запись с seq=2 может быть обработана до записи с seq=1, или запись с seq=3 можно прочитать до записи с seq=2
2. не хватает партиции: адрес записи состоит из трёх частей!
3. чтение в Kafka ничего не удаляет, в отличии от RabbitMQ. после чтения ничего не происходит
4. порядок событий будет таким же, строго таким как добавили. два консьюмера из трёх будут простаивать
5. нужно обеспечить правильный порядок обработки события по одному user_id и, но если обработать сначала одну партицию, потом вторую то порядок будет нарушен
        у A и B свои счётчики. Если оба начали с 1, каждый выдаст своё seq=5. Получатся два разных события с одинаковым seq, и нумерация «1, 2, 3… без пропусков» теряет смысл.
6. для Key=None возможна случайная партиция, для key=b'' - всё равно строго определённая
